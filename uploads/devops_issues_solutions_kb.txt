DEVOPS ISSUES & SOLUTIONS — ENTERPRISE KNOWLEDGE BASE
============================================================

Purpose
-------
This document contains realistic sample DevOps Knowledge Base (KB) articles
for project testing, RAG evaluation, support training, and troubleshooting.
All hostnames, namespaces, IDs, URLs, and values are SAMPLE data only.
Do not use sample credentials or commands against production without approval.

KB-DEV-001 — Linux Disk Space Full
-----------------------------------
Category: Linux / Infrastructure
Symptoms:
- Application cannot write logs or temporary files.
- "No space left on device" errors.
- Services may fail to start.

Impact:
Application outages, failed deployments, and log loss.

Possible Causes:
1. Large application logs.
2. Old package/cache files.
3. Deleted files still held by processes.
4. Temporary files consuming disk.

Troubleshooting:
1. Check filesystem usage:
   df -h
2. Identify large directories:
   sudo du -xh /var | sort -h | tail -20
3. Check log files:
   sudo du -sh /var/log/*
4. Check deleted-but-open files:
   sudo lsof +L1
5. Review whether log rotation is working.

Solution:
- Remove approved obsolete files.
- Configure logrotate.
- Archive required logs before deletion.
- Restart a process holding deleted files only after change approval.

Validation:
df -h
Confirm filesystem usage is below the operational threshold and application
writes succeed.

Prevention:
Configure log rotation, disk alerts, retention policies, and periodic cleanup.

Escalation:
Escalate if the filesystem remains full after approved cleanup or if a
database/system partition is affected.


KB-DEV-002 — Linux Service Failed to Start
------------------------------------------
Category: Linux / Service Management
Symptoms:
- systemctl reports failed state.
- Application is unavailable after reboot.

Troubleshooting:
1. Check status:
   systemctl status sample-app
2. Review recent logs:
   journalctl -u sample-app --since "30 min ago"
3. Check configuration and dependencies.
4. Check ports:
   ss -lntp
5. Check filesystem and permissions.

Solution:
Correct the identified configuration, permission, dependency, or port issue.
Then:
   sudo systemctl daemon-reload
   sudo systemctl restart sample-app

Validation:
   systemctl is-active sample-app
   curl -f http://localhost:8080/health

Prevention:
Use startup health checks, configuration validation, and monitoring.


KB-DEV-003 — Git Merge Conflict
--------------------------------
Category: Git / Source Control
Symptoms:
- Pull or merge reports conflicts.
- CI pipeline cannot build the branch.

Troubleshooting:
   git status
   git diff
Identify conflicted files and understand both changes before editing.

Solution:
1. Edit conflicted files.
2. Remove conflict markers.
3. Test the code.
4. Stage resolved files:
   git add <file>
5. Continue:
   git commit
   or, for rebase:
   git rebase --continue

Validation:
   git status
   git diff HEAD
Run unit tests and the normal CI checks.

Prevention:
Keep branches short-lived, sync frequently, and use clear ownership.


KB-DEV-004 — Git Push Rejected
--------------------------------
Category: Git / Source Control
Symptoms:
- "rejected because remote contains work".
- Push fails after another developer updated the branch.

Solution:
First inspect the remote:
   git fetch origin
   git log --oneline HEAD..origin/main

If appropriate:
   git pull --rebase origin main
Resolve conflicts, test, then:
   git push

Avoid force-pushing shared branches unless explicitly approved.

Validation:
Confirm the branch is synchronized with the remote and CI starts normally.


KB-DEV-005 — Docker Image Build Fails
-------------------------------------
Category: Docker / Container
Symptoms:
- docker build exits with an error.
- Dependency installation fails.
- Dockerfile instruction fails.

Troubleshooting:
1. Build with full output:
   docker build --progress=plain -t sample-app:test .
2. Verify build context.
3. Check COPY paths.
4. Validate package versions.
5. Check base image availability.
6. Review .dockerignore.

Solution:
Correct Dockerfile syntax, paths, dependency versions, or base image
configuration. Rebuild without relying on stale cache when necessary:
   docker build --no-cache -t sample-app:test .

Validation:
   docker image inspect sample-app:test
Run the container and execute its health check.


KB-DEV-006 — Docker Container Exits Immediately
------------------------------------------------
Category: Docker / Runtime
Symptoms:
Container starts and immediately changes to Exited.

Troubleshooting:
   docker ps -a
   docker logs <container>
   docker inspect <container>

Check:
- ENTRYPOINT/CMD
- Environment variables
- Application startup command
- File permissions
- Required configuration

Solution:
Correct the startup command/configuration and rebuild or recreate the
container.

Validation:
   docker run --rm -p 8080:8080 sample-app:test
   curl http://localhost:8080/health


KB-DEV-007 — Docker Container Cannot Reach Another Service
-----------------------------------------------------------
Category: Docker / Networking
Symptoms:
- Connection refused.
- DNS name cannot be resolved between containers.

Troubleshooting:
   docker network ls
   docker network inspect sample-network

Confirm both containers are attached to the same user-defined network.
Use the service/container name rather than localhost for inter-container
communication.

Solution:
Create/use a shared network and configure the application endpoint correctly.

Validation:
Test DNS resolution and TCP connectivity from the application container.


KB-DEV-008 — Kubernetes Pod CrashLoopBackOff
--------------------------------------------
Category: Kubernetes / Workload
Symptoms:
- Pod repeatedly starts and crashes.
- kubectl shows CrashLoopBackOff.

Troubleshooting:
   kubectl get pods -n sample-app
   kubectl describe pod <pod> -n sample-app
   kubectl logs <pod> -n sample-app
   kubectl logs <pod> -n sample-app --previous

Check:
- Application startup errors
- Environment variables
- Secrets/configuration
- Dependency availability
- Resource limits
- Probe configuration

Solution:
Fix the actual startup problem and redeploy. Do not simply increase
resources without evidence.

Validation:
   kubectl rollout status deployment/sample-app -n sample-app
   kubectl get pods -n sample-app


KB-DEV-009 — Kubernetes Pod Pending
-----------------------------------
Category: Kubernetes / Scheduling
Symptoms:
Pod remains Pending and never starts.

Troubleshooting:
   kubectl describe pod <pod> -n sample-app

Check Events for:
- Insufficient CPU/memory
- Node selector mismatch
- Taints/tolerations
- PVC not available
- Scheduling constraints

Solution:
Correct resource requests, scheduling rules, node capacity, or storage
configuration according to the identified cause.

Validation:
Pod reaches Running/Ready state and deployment becomes available.


KB-DEV-010 — Kubernetes ImagePullBackOff
----------------------------------------
Category: Kubernetes / Container Registry
Symptoms:
- ImagePullBackOff or ErrImagePull.
- Pod cannot download its container image.

Troubleshooting:
   kubectl describe pod <pod> -n sample-app

Verify:
- Image name/tag
- Registry availability
- Image existence
- imagePullSecrets
- Node network access

Solution:
Correct image reference or registry authentication. For private registries,
configure the approved imagePullSecret.

Validation:
Pod starts successfully and uses the expected image.


KB-DEV-011 — Kubernetes Service Not Reachable
---------------------------------------------
Category: Kubernetes / Networking
Symptoms:
- Application pods are Running.
- Service returns connection errors or no endpoints.

Troubleshooting:
   kubectl get svc -n sample-app
   kubectl get endpoints -n sample-app
   kubectl get pods --show-labels -n sample-app

Check whether Service selectors match Pod labels.

Solution:
Correct the Service selector, targetPort, or application listening port.

Validation:
Test the Service from an appropriate test pod and verify endpoints exist.


KB-DEV-012 — Kubernetes Readiness Probe Failure
-----------------------------------------------
Category: Kubernetes / Health Checks
Symptoms:
Pod is Running but not Ready.

Troubleshooting:
   kubectl describe pod <pod> -n sample-app
Review probe events and test the health endpoint manually.

Common causes:
- Wrong path
- Wrong port
- Application startup slower than probe timing
- Authentication incorrectly required on health endpoint

Solution:
Correct probe path/port or tune initialDelaySeconds/timeoutSeconds based on
measured startup behavior.

Validation:
Pod reports READY 1/1 and Service endpoints include the pod.


KB-DEV-013 — Kubernetes ConfigMap/Secret Configuration Issue
-------------------------------------------------------------
Category: Kubernetes / Configuration
Symptoms:
Application starts with incorrect settings or reports missing environment
variables.

Troubleshooting:
   kubectl describe deployment sample-app -n sample-app
   kubectl get configmap -n sample-app
   kubectl get secret -n sample-app

Never print secret values into tickets or logs.

Solution:
Correct the ConfigMap/Secret reference and restart the workload if required.

Validation:
Application reports expected non-sensitive configuration and passes health
checks.


KB-DEV-014 — Kubernetes Deployment Rollout Stuck
------------------------------------------------
Category: Kubernetes / Deployment
Symptoms:
Deployment does not complete rollout.

Troubleshooting:
   kubectl rollout status deployment/sample-app -n sample-app
   kubectl get rs -n sample-app
   kubectl describe deployment sample-app -n sample-app

Check for:
- Failed new pods
- Insufficient capacity
- Probe failures
- Image pull failures
- Scheduling errors

Solution:
Fix the root cause. If the release itself is defective and rollback is
approved:
   kubectl rollout undo deployment/sample-app -n sample-app

Validation:
Rollout completes and application health checks pass.


KB-DEV-015 — CI Pipeline Fails During Dependency Installation
--------------------------------------------------------------
Category: CI/CD / Build
Symptoms:
Pipeline fails during npm/pip/maven/gradle package installation.

Troubleshooting:
1. Identify exact package and error.
2. Check lockfile consistency.
3. Check private repository authentication.
4. Verify runner network access.
5. Check supported runtime version.

Solution:
Pin compatible dependency versions, update lockfiles, or correct repository
configuration. Avoid blindly upgrading all dependencies during incident
resolution.

Validation:
Run the same dependency installation in a clean runner.

Category: CI/CD / Azure DevOps
Symptoms:

Troubleshooting:
- Check agent pool status.
- Verify self-hosted agent service.
- Check machine connectivity.
- Review agent logs.
- Check disk and CPU utilization.

Solution:
Restore the agent service/connectivity or route the job to an approved
available agent pool.

Validation:
Run a small test pipeline and confirm the agent completes a job.

KB-DEV-021 — Application Cannot Connect to Database
---------------------------------------------------
Category: Cloud / Database / Networking
Symptoms:
Connection timeout, refused connection, or authentication error.

Troubleshooting:
Separate the problem into:
1. DNS resolution
2. Network route
3. Firewall/security group
4. Port reachability
5. Authentication
6. Database availability
7. Connection pool configuration

Solution:
Fix only the failing layer. Do not expose passwords in tickets or logs.

Validation:
Perform an approved connectivity test and application health check.


KB-DEV-022 — High CPU Usage on Application
------------------------------------------
Category: Monitoring / Performance
Symptoms:
CPU remains above the defined operational threshold.

Troubleshooting:
1. Check time range and affected instances.
2. Identify deployment correlation.
3. Review application metrics.
4. Check traffic volume.
5. Inspect slow operations.
6. Check for runaway processes.

Solution:
Depending on evidence, optimize code, reduce unnecessary work, scale out,
or adjust resource allocation according to capacity policy.

Validation:
CPU returns to normal range and application latency/error rate is healthy.


KB-DEV-023 — Memory Leak / OOMKilled Pod
----------------------------------------
Category: Kubernetes / Performance
Symptoms:
Pod terminates with OOMKilled.

Troubleshooting:
   kubectl describe pod <pod> -n sample-app
Review memory requests/limits and application memory metrics.

Solution:
Determine whether the issue is:
- Actual memory leak
- Increased workload
- Undersized limit
- Unbounded cache

Increase limits only as a temporary/validated measure; investigate application
behavior for persistent OOM events.

Validation:
Monitor memory over several workload cycles.

----------------------------------
Category: Networking / Web Server
Symptoms:
Users receive HTTP 502 from Nginx/reverse proxy.

Troubleshooting:
1. Check Nginx error log.
2. Verify upstream application is running.
3. Verify upstream host/port.
4. Check DNS.
5. Test upstream directly.
6. Check timeout configuration.

Solution:
Restore upstream availability or correct proxy configuration.

Validation:
Test the application through the proxy and confirm successful HTTP response.


KB-DEV-025 — TLS/SSL Certificate Expiry
---------------------------------------
Category: Security / Networking
Symptoms:
Browser/API client reports certificate expired or invalid.

Troubleshooting:
Check certificate expiry and the complete certificate chain using approved
tools. Identify whether the certificate is managed by the load balancer,
ingress, reverse proxy, or certificate platform.

Solution:
Renew and deploy the approved certificate. Verify chain and hostname.

Validation:
Test from an external client and confirm the new expiry date.

Prevention:
Set certificate-expiry monitoring well before the renewal deadline.

KB-DEV-027 — Deployment Rollback Required
-----------------------------------------
Category: Release Management
Symptoms:
A new release causes elevated errors, failed health checks, or major
functional regression.

Troubleshooting:
1. Confirm correlation with the deployment.
2. Check error rate and logs.
3. Identify affected version.
4. Confirm rollback criteria.
5. Obtain required approval.

Solution:
Use the platform's approved rollback mechanism. Example Kubernetes:
   kubectl rollout undo deployment/sample-app -n sample-app

Validation:
Confirm previous version is healthy and error rate returns to baseline.

Prevention:
Use canary/blue-green strategies, automated health checks, and rollback
procedures.

Category: Infrastructure as Code
Symptoms:
terraform plan/apply fails.

Troubleshooting:

   terraform plan

Check:
- Provider authentication
- State locking
- Resource dependency
- Variable values
- Policy restrictions

Solution:
Resolve the specific provider/state/configuration error. Never manually

KB-DEV-029 — Terraform State Lock
---------------------------------
Category: Infrastructure as Code
Symptoms:
Terraform reports that the state is locked.

Troubleshooting:
Identify the active operation and verify whether another deployment is
running. Do not force-unlock a state that may still be in use.

Solution:
If the lock is stale and the organization's approved procedure confirms it,
use the documented force-unlock process with the exact lock ID.

Validation:
A new plan/apply completes and state remains consistent.

- Threshold

KB-DEV-032 — Security Scan Blocks CI Pipeline
---------------------------------------------
Category: DevSecOps / Security
Symptoms:
SAST, dependency, container, or IaC scan fails the pipeline.

Troubleshooting:
Identify:
- Vulnerability ID
- Severity

KB-DEV-033 — Kubernetes RBAC Permission Denied
----------------------------------------------
Category: Kubernetes / Security
Symptoms:
User/service account receives "forbidden" or "cannot list/get/create".

Troubleshooting:
   kubectl auth can-i get pods -n sample-app
   kubectl auth can-i create deployments -n sample-app

Review Role/ClusterRole and RoleBinding/ClusterRoleBinding.

Solution:
Grant the minimum required permission using least privilege. Avoid
cluster-admin unless explicitly justified and approved.

Validation:
Required operation succeeds while unrelated privileged operations remain
denied.


KB-DEV-034 — GitHub/Azure Secret Exposed in Repository
-------------------------------------------------------
Category: DevSecOps / Secrets
Symptoms:
A credential/token/key is committed to source control.

Immediate Actions:
1. Treat the credential as compromised.
2. Revoke/rotate it immediately through the approved secret owner.
3. Remove it from active code/configuration.
4. Review access logs where appropriate.
5. Use secret-management tooling.

Important:
Removing a secret from the latest commit does not necessarily remove it from
Git history. Follow the organization's approved history-rewrite procedure.

Prevention:
Use secret scanning, pre-commit checks, managed secret stores, and short-lived
credentials.


KB-DEV-035 — Production Deployment Failed Due to Missing Environment Variable
-------------------------------------------------------------------------------
Category: Deployment / Configuration
Symptoms:
Application starts locally but fails in deployment.

Troubleshooting:
Compare required configuration between environments without exposing secret
values. Check deployment manifests, variable names, configuration injection,
and secret references.

Solution:
Add the missing approved configuration through the correct configuration or
secret-management process.

Validation:
Deployment starts, health checks pass, and application logs show no missing
configuration errors.


STANDARD DEVOPS INCIDENT WORKFLOW
=================================

1. Detect
   - Alert, ticket, monitoring event, user report, or pipeline failure.

2. Classify
   - Infrastructure
   - Application
   - Network
   - CI/CD
   - Kubernetes
   - Cloud
   - Security
   - Observability

3. Assess Impact
   - Number of users/services affected
   - Production/non-production
   - Availability and business impact
   - Recent changes

4. Troubleshoot
   - Collect evidence before changing configuration.
   - Check logs, metrics, events, recent deployments, and dependencies.
   - Change one relevant variable at a time where possible.

5. Recover
   - Apply the approved fix or rollback.
   - Validate health and business functionality.

6. Document
   - Root cause
   - Timeline
   - Actions taken
   - Validation evidence
   - Preventive action

7. Close
   - Confirm with stakeholders.
   - Update the KB/runbook if the incident exposed a documentation gap.
